# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Tally (tally, formerly duizhang/对账) — a Chinese financial-report **closed-world fact Agent** ("every answer must be reconcilable against the source"). v0.7 contract: every fact in an answer comes ONLY from internal RAG evidence — LLM param knowledge organizes language but never produces facts; the tool whitelist holds internal actions only (search / metrics_table / derive) — never a browser, external API, or model-generated code; only verify:pass structured facts enter long-term memory. Since v0.5.1 the LLM defaults to a LOCAL Ollama model (zero key/cost/egress; the model TIER is user-configured via `TALLY_LLM_MODEL` — the built-in default is a small tier that runs on most machines, see `llm.DEFAULT_MODEL`; design assumptions never hardcode a tier — stronger tiers improve narration while the gates keep the floor): it drives query understanding, routing, retrieval grading, rewriting, multi-company compare decomposition, and grounded generation. Deterministic code owns the exit gate (`verify_citations`): degrade or refuse, never fabricate. The rule mode (`heuristic`) remains as the zero-key fallback and regression baseline — same graph, two brains.

All code comments, docstrings, docs, and commit messages are in Chinese — follow that convention.

## Commands

```bash
source venv/bin/activate                # Python 3.12; deps already installed

# Ingest & query (auto = llm if key in .env, else heuristic)
python -m tally.cli ingest samples/  # incremental ingest (fingerprint diff; idempotent)
python -m tally.cli ingest samples/ --watch   # poll mode: resync every 60s
python -m tally.cli ask "欧科亿 2026 年半年度预计净利润多少"
python -m tally.cli ask "对比欧科亿和海伦哲 2026 一季度谁赚得多"   # compare → decompose
python -m tally.cli chat               # 多轮对话（L0 记忆：追问继承公司/期间/指标/年份）
python -m tally.cli ask "…" -v          # 诊断态：trace 每节点带耗时（stderr）
python -m tally.cli ask "…" --json      # 机器态：整态 JSON
python -m tally.cli eval --json         # 机器态：summary+行级 rows（对比脚本用）
python -m tally.cli eval                          # default dataset (10 单跳; CI regression)
python -m tally.cli eval --mode llm --dataset agent     # agent dataset (multi-hop; fine on the default local tier)
python -m tally.cli eval --dataset innolight      # 中际旭创真值 31 题（事实/趋势/陷阱/鲁棒；CI 冒烟）
python -m tally.cli eval --dataset innolight --min-retrieval 1.0 --min-hit 1.0   # CI 门槛：低于即非零退出（ci.yml 已挂）
python -m tally.cli eval --dataset maotai         # 贵州茅台真值 9 题（简称/口径/断词泛化）
python -m tally.cli eval --dataset quarters       # v0.7 单季差分派生 8 题（Q2=H1−Q1 / Q4=FY−Q3）
python -m tally.cli eval --dataset multihop       # v0.7 多跳 8 题（跨年双值/三公司/多指标族）
python -m tally.cli eval --dataset multiturn      # v0.7 多轮 10 轮接力（L0 继承链）
python -m tally.cli docs             # list ingested docs
python -m tally.cli index            # (re)build FTS for existing chunks
python -m tally.cli embed            # 可选向量第三路：嵌入存量 chunks（需 requirements-vec.txt）

# Tests / lint
pytest                                  # 123 cases; conftest blocks all real LLM calls
pytest tests/test_store.py::test_readd_after_drop_no_ghost   # one test
ruff check .                            # lint (CI enforces)
```

Corpus layout: `samples/` = small demo set; `data/corpus/` = full corpus (1,104 docs / 60.7万 chunks); `data/中际旭创/` = ground-truth corpus for the innolight dataset (10 docs / 7,873 chunks, **26MB committed to git** — CI ingests it and runs the 31-题 truth smoke; the innolight eval is not reproducible without this corpus); `data/贵州茅台/` = second-company corpus (10 docs / 6,518 chunks, ~10MB committed, same 2024–2026 period structure — anchors the 9-题 maotai truth set, the multi-company generalization baton). Roots coexist in one DB (multi-root ingest). Eval logic lives in `evalx.py` (`judge()` is a pure function; drop custom datasets into `evals/*.json`).

After changing retrieval/graph/answer code, run `python -m tally.cli eval --mode heuristic` (deterministic baseline — plain `eval` defaults to `auto`, which silently goes llm when Ollama is up and adds small-model variance) and verify the three headline metrics don't regress (full corpus: 1.00/1.00/1.00); `evalx.py` additionally reports citation_coverage (pass/coverage; named faithfulness before v0.7) and chunk-level P/R@8 — check those too on retrieval changes. Bug fixes follow TDD — failing test first, watch it fail, then fix (DESIGN-v0.4.md §5 and DESIGN-v0.5.md record two such rounds).

Secrets: `TALLY_LLM_API_KEY` lives ONLY in `.env` (gitignored; `_load_dotenv` loads it, env vars take precedence). Never write the key into code, docs, sample commands, or git history. Default channel is LOCAL Ollama via its NATIVE `/api/chat` (`llm._local_chat`): the OpenAI-compat `/v1` endpoint ignores the `think` param, `/no_think` soft switch is dead in Qwen3.5, and thinking starves max_tokens leaving content empty (all three measured — DESIGN-v0.5.md D7). Local endpoints need no key (`llm_enabled` is True for localhost). `think` defaults OFF locally (~×5 latency when on). Remote options via `.env`: any OpenAI-compatible endpoint, or Anthropic-compatible (`_use_anthropic`; thinking counts toward max_tokens → budget ×8). Requires Ollama ≥ 0.40. Other env: `TALLY_DB`, `TALLY_LLM_MODEL`, `TALLY_LLM_MAX_TOKENS`, `TALLY_LLM_THINKING`, `TALLY_TREND_ANALYSIS` (trend 意图的 LLM 叙述层， three states since v0.6.5: unset = narration ON by default behind double gates — the number gate plus `direction_gate` (direction words vs skeleton YoY signs; catches 「+90.05% narrated as 大幅回落」); `enabled` = adds deep investment analysis; `off` = skeleton only, the escape hatch; a gated narration degrades to skeleton = pre-v0.6.5 behavior, conservative failure), `TALLY_SELF_CHECK` (LLM judge on the surviving narration, default ON — structured `{faithful/on_topic/sensitive}`; ASYMMETRIC TRUST: the judge can only veto/degrade (sensitive → strip sentences, never rewrite; unfaithful/off-topic → one bounded repair, then skeleton), it can never unlock or bypass the deterministic gates, which run first), `TALLY_VEC` (vector third track, default OFF — see Retrieval), `TALLY_MEMORY` (three-tier memory master switch, default ON; `off` = v0.6.5 no-memory behavior) and `TALLY_EVAL_MEMORY` (eval-only override to re-enable the L1 ledger inside evals; default isolates it).

## Architecture

Two planes, one SQLite file (`docs` / `chunks` / `fts_w` / `fts_c` / `manifest`, plus optional `vecs` / `vecmeta`):

**Offline ingest** — `source.py` scans a directory into `{path: mtime_ns-size fingerprint}` and three-way diffs against the `manifest` table (add/update/delete + orphan cleanup scoped to the scan root). `ingest.py` extracts metadata from the filename (巨潮 convention → company/period/kind — never from model guessing; broker-report naming `日期-券商-公司` also parses; md/txt with a CJK company-name stem ingest as ANALYSIS, **anything else is rejected with ⚠** — a digit-stem like `20261009_…分析.md` used to become garbage doc-id `20261009_MD`), strips repeated header/footer lines (frequency-based, digits stripped in normalization — headers share lines with page numbers), chunks with table-awareness, and appends number-normalization notes (`41,914.72 万元` → `≈4.19亿`) so lexical search hits 「多少亿」-style queries.

**Online QA graph** (`graph.py`) — LangGraph state machine over `GraphState` (narrow-interface TypedDict; `trace` has append semantics):

```
START → understand ─→ route ─metric/compare(llm)──→ agent_research（工具循环：单一 search 工具，
       （LLM 抽取          │                          模型自主迭代检索，步数≤6，幂等缓存+重复收手，
        intent/公司/期间，   │─metric/compare(heuristic)→ retrieve/decompose→grade⇄rewrite  理解先验优先）
        规则兜底）          │─trend（双模式共用）──→ trend_research（确定性遍历最近 6 期，
                           │─summary→ summarize_doc    「主要会计数据」锚定，时间升序）
                           │                          ↓ generate → verify_citations（确定性闸门）
                           └─other──→ refuse
```

**Memory 三层**（v0.7 Phase 3，`memory.py` + `store.py` verified_facts 表，DESIGN-v0.7 §7）— L0 会话记忆：`cli chat` 与 multiturn eval 把轮摘要传进 `new_state`（近 3 轮全量 q+答案截断，更早压缩为结构化轮摘要——丢自由文本不丢理解字段）；继承只取 understanding 字段（companies/period/years）与指标词，**永不继承自由文本**；裸追问（「呢/它」）带任何数据信号时意图救援为 metric 而非 other。L1 事实台账：`verified_facts` 表键寻址 (company, period, metric, caliber)，合并算子 noop/insert/conflict/restated/reingest（比较 value_std，append-only supersede，部分索引 WHERE superseded_by IS NULL）；**写闸** = verify:pass ∧ 口径闸未触发（trace 含 caliber-mismatch/fallback/no-evidence/derived-mismatch 一律不写）；**读不豁免**——memory_probe 命中拼出的答案内联过 verify（缓存证据不缓存结论）；失效 = 语料指纹（probe 时校验，指纹漂移自动 supersede reingest）。业绩预告文档（E 后缀期间）是区间值非单值——metric_rows 解析不出单值，不落账（保守失败，正确行为）。L2 固定语义资产：`tally/assets/semantic_assets.json`（alias 词典等检索导航知识，非答案事实）。开关：`TALLY_MEMORY=off` 退回 v0.6.5 无记忆行为；eval 默认隔离台账（`TALLY_EVAL_MEMORY=on` 才放开）——防把检索能力测成记忆命中。

**Planner**（v0.7 Phase 2，llm 模式）— 多跳信号（≥3 公司 / 跨年 / ≥2 指标族）触发 `plan` 节点：LLM 输出结构化子目标 JSON，`_validate_plan` **只删不造**（白名单外动作丢、期间规约、去重、MAX_SUBGOALS 封顶、单公司回填），执行后子目标检查点（`_ckpt_ok`：财报级数字在场 ∧ 指标词命中）逐个验证，未过检查点的子目标进 `plan_gaps`（部分答案不硬凑）。

**derive 差分算子**（v0.7 Phase 4）— 原文不披露单季时：Q2 = H1(半年累计) − Q1、Q4 = FY − Q3(前三季累计)，操作数同为年初至期末累计（口径对齐），**原币精度**算术（亿值四舍五入差分会到百万级）；`_derived_ok` 出口重算：操作数必须真在场于证据池且 |a−b−value| ≤ 0.01；`_derive_quarters.find` 按 tag+年份匹配（只按 tag 会把 2024Q2 派生到 2025 行——实测回归）。**禁止模型心算**（封闭世界：算术也是事实）。

**trend 意图**（v0.6.2，v0.6.5 升级）— `trend_research` deterministically walks the company's reporting periods (≤6, chronological — small models left periods out / looped when asked to do it themselves), then `trend_skeleton` parses each period into structured rows （营收/归母净利 + 同比 + 引用； Q3 dual-column rows anchor the cumulative column — D26). Since v0.6.5 the LLM narration layer is **ON by default** behind double gates (number gate + `direction_gate`: direction words vs skeleton YoY signs) plus an LLM judge (`_self_check`, asymmetric trust — veto-only, never unlock; sensitive → strip sentences, never rewrite; unfaithful → one bounded repair); any gate firing degrades to skeleton = pre-v0.6.5 behavior (conservative failure). No fact rows → refuse. Two guards: query must contain a trend word or intent downgrades to metric (small models hallucinated trend for 「预计…多少」); rule layer overrides when the LLM misjudges trend as summary. Multi-period evidence still exits through generate→verify.

**Retrieval** (`fts.py` + `index.py`) — dual-track FTS5 + RRF (k=60): word track (jieba + unicode61) and char track (trigram, whitespace-stripped, ≤200 chars — truncates 14.2% of chunks by design, word track covers full text). An optional third vector track (`embed.py`: bge-small-zh-v1.5 @ fastembed, same RRF) is **default OFF** — opt in via `TALLY_VEC=on` + `pip install -r requirements-vec.txt` + `cli embed`; the 31-题 truth ablation (DESIGN-v0.6 §8.3, D19) found lexical dual-track already saturated on numeric/caliber tasks while embeddings pull semantically-near-but-wrong-caliber chunks (net negative). Missing dep / model mismatch / un-embedded DB → `ranking()` returns None → silent dual-track fallback (CI runs without fastembed). `understanding` (from the understand node) drives `doc_scope`: exact company match + period restriction at the doc level (period *type* + *year* — `query_years` extracts 20xx and colloquial two-digit years 「15年」→2015, must be followed by 年 to avoid amount false-positives). `expand_query` maps colloquial terms to report terminology (营收→营业收入, 赚→净利润, 原因→主要系). Generation context is assembled by `page_evidence` (small-to-big, DESIGN-v0.6 §5.3: dedup top-hit pages → ±2 sibling-chunk window → hard cap); metric intent additionally fronts the 「主要会计数据」 table page (truth rows lose lexical fights to number-less header chunks — measured).

### Invariants — violate these and you reintroduce past bugs

1. **`Store` (`store.py`) is the ONLY writer to the six tables** (vecs/vecmeta included — `add_vecs`/`set_vec_model` are the only vector writers; changing the vecmeta model wipes all stale vecs). fts rowids align to `chunks.rowid`; re-add = drop-then-insert (never `INSERT OR REPLACE` on chunks), and drop_doc clears the doc's vecs rows. `chunks(doc_id)` is indexed in SCHEMA (legacy DBs auto-migrate on next Store open). `tests/test_store.py` is the permanent regression guard.
2. **One graph, two brains.** Every LLM decision point falls back to rules on failure **with a trace marker** (`understand:llm→fallback` etc.). `--mode auto` resolves at `new_state`: llm if key present, else heuristic. Tests never make real LLM calls (conftest strips the key).
3. **The corrective loop is bounded** (`MAX_RETRIES = 1` heuristic; `MAX_AGENT_STEPS = 6` for the agent loop). llm-mode metric/compare route into `agent_research` — an engineered **ReAct loop** (LOCAL channel only — remote channels raise NotImplementedError in `chat_with_tools` and the loop falls back to the fixed pipeline with trace `agent:fallback`; answers unaffected, same verify gate; DESIGN-v0.7 §8) (`AGENT_TOOLS` registry: `search` / `metrics_table` / `derive`; tool call → observation fed back as tool role → next action → self/budget stop). Step-level spans are OBSERVED since v0.7: each step records the four-tuple `{thought, action, obs(条数+首doc), gate(new/dup/empty)}` + per-step ms into `state["agent_steps"]` (`-v` prints, `--json` serializes, evalx aggregates waste_rate = (dup+empty)/calls as the measurable eₖ proxy — DESIGN-v0.7 §3 度量先行); trend never enters the loop (deterministic walk, both modes). Guardrails the loop needs with small models (all measured, DESIGN-v0.6.md): idempotent call cache + early stop on all-repeat batches; understanding priors OVERRIDE tool args for period (small models hallucinate FY) and backfill company/period when omitted; agent search terms are written into `effective_query`; evidence pool emits round-robin by doc. Agent-collected evidence still goes through generate→verify — autonomy never exempts the gate.
4. **Refusal over fabrication.** Gates: period guard in `route` (year from doc metadata, not the model); doc-level period filter (`period_hints` is mutually exclusive — "半年度" contains "年度", substring-ordered ifs let FY leak, round-4 bug R-1; bare year + no period word → FY since D18); `verify_citations` (evidence pool = page-level set **∪ hits** — page windows only cover hits[:4] while extractive quotes hits[:8]; citation matching is whitespace-normalized since D13 — small-model citation formats drift 「第 8 页」; cited chunks incl. num_notes, meta-token-filtered both sides, numeric sentences only, newline-aware splitting; < 0.45 → degrade to extractive; LLM no-evidence → extractive, not refuse). Metric caliber is guarded at **five layers** since D16/D20–D22: `stitch_adjacent` re-joins same-page label/number table chunks (runs in retrieve AND agent paths); trend `pick()` is LINE-level (splitlines, first big number after the indicator word, label-context caliber guard = 20 chars before the indicator, rank-fallback when the best line fails parse) and extractive scoring both refuse 扣非 rows unless the query asks 扣; **paired-caliber demotions ×5** in extractive (asking X demotes sibling-Y sentences that share label-prefix tokens: 扣非↔归母 / 净利润↔净资产 / 总收入↔营业收入 / 总资产↔净利润族 / 总资产↔营收族); and `caliber_mismatch` (D22) — an LLM-mode numeric gate: asking a named caliber (扣非/总收入/净资产/总资产) requires the answer's big numbers to appear in that caliber's labeled rows (source = page set ∪ hits, next-line pickup for split label/value rows, segment-cut for 营业总收入) else degrade to extractive — the first closing of the gate≠correctness boundary (§9). `ans.SPLIT_FIX` broken-label repairs are shared by extractive / trend pick / generate evidence assembly — keep the three in sync. Fronting (`front_key_table`, cap 8 ∪ metric-word-matching tail chunks) runs in BOTH retrieve and agent paths; extractive window is hits[:12]; `page_evidence` is page-stratified (first-hit ±2 window per page — the union-window variant measured net-negative on small models, context dilution).
5. **SQLite PRAGMAs are per-connection** (`fts._apply_pragmas` every search; Store sets WAL + synchronous=NORMAL; `store.analyze()` after changed ingests).
6. **Multi-root ingest**: deletion/orphan cleanup scoped to the scan root (`under_root` in `cli.py`). `--rebuild` still wipes everything.
7. **Thinking is tiered** (`llm._thinking_off`): structured calls off (cheap enums), generation on (number association on fragmented table evidence needs it; flash without thinking quotes increase-ranges as metric values). The `extra_body.thinking` param is sent ONLY to bigmodel endpoints.
