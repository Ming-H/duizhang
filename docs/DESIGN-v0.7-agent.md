## 0. 定位与背景

**语料定位（用户设定）**：财报是**专属内部资料**——LLM 的参数知识
**不得**用于产出事实，外部工具（浏览器/第三方 API）**不得**用于查询
事实；一切事实只能从内部 RAG 检索的证据中来。这不是限制，是这类
系统的**正确形态**：封闭世界（closed-world）让「对账」成为可判定
的问题——开放世界里 verify 永远证伪不了「模型碰巧知道」。

这个定位下，duizhang 的 Agent 性不是「能调多少外部工具」，而是
**在严格证据边界内把自主性做深**：自主规划检索、自主反思修正、
自主判断收手——同时每一步都可被确定性代码否决。

**是 Agent，不是聊天机器人**：聊天界面只是表面。判据——智能在
架构不在模型；状态是结构化的（GraphState/账本/台账，不是对话流）；
行动改变环境（检索扩充证据池）；终止是设计内结局（自主收手/预算
截断/闸门拦截）；质量是**轨迹级系统属性**而非单轮好坏；失败形态
是安全失败（降级/部分答案/拒答）而非自信说错。现状缺的不是 Agent
形态，是 Agent 的**时间维度**——多轮会话与跨会话记忆（Phase 3
补），也正是长程可靠性（§3）开始真正承压的地方。

### 1.4 环境与观察回路（ReAct）

**`agent_research` 就是一个工程化的 ReAct 环**，此前文档未认领：
行动=模型写工具调用；观察=`run_search` 结果以 tool role 回灌
（doc/page/text JSON）；观察驱动下一步（重复观察→提示换角度→
整批重复=收手）；终止=模型自主收手（`self`）或预算截断（`budget`）。
护栏全部实测驱动：步数硬上限、幂等缓存、理解先验覆盖工具参数、
证据按文档轮转。出口不豁免 generate→verify。

缺口：**Thought 不可见**——`resp["content"]`（模型步间陈述）进了
msgs 但不进 trace/`--json`，无法重放「模型为什么这么查」；步级
耗时 span 也没有（观测是整节点粒度）。

## 2. 封闭世界契约（Agent 宪章）

升级后写入 README 首节与 CLAUDE.md，作为一切 Agent 能力的边界：

1. **事实唯一来源**：答案中的每个事实（数字/方向/引文）只能来自
   内部 RAG 检索的证据。LLM 参数知识可用于语言组织，不得产出事实。
2. **工具白名单**：可扩展，但白名单只含内部动作（search /
   metrics_table / derive）。永无浏览器、外部 API、模型生成代码。
3. **记忆回写必须过闸**：写入长期记忆的内容只能是 `verify:pass` 的
   结构化事实（公司/期间/指标/数值/引用），不写自由文本——回写
   闸与出口闸同源。
4. **分工恒定**：LLM 决定「怎么查、怎么讲」；确定性代码决定
   「对不对、能不能出门」。任何 Agent 能力（规划/记忆/工具）都
   不豁免 `verify_citations` 与各口径闸。

## 3. 长程可靠性公理（v0.7 的核心风险与解法）

**为什么是核心风险**：v0.7 之前单次 ask 的 LLM 步数有限（~4-6）；
v0.7 第一次把链拉长——多子目标规划、多轮会话、跨会话记忆。单步
95% 可靠的任务，20 步成功率只剩 ~36%（0.95²⁰）：任何一环的幻觉/
误判都被后续放大。**拉长链之前必须先装可靠性设施**——这是分期
顺序（观测→规划→记忆→工具）的根本理由。

**该改的不是单步精度，是传播结构**。朴素公式 P(成功)=pⁿ 的隐藏
假设是「错误一旦发生必然传播到终点（传播率=1）」；工程上真正
可动的是传播率：

```
P(错误答案) ≤ Σₖ eₖ·gₖ    eₖ = 第k步出错率（模型决定）
                           gₖ = 该错误穿过第k步闸门的存活率（代码决定）
e=5%、g=2%、20 步 → ≤ 2%（朴素模型 36% 失败）
```

且失败形态改变：被拦的错误变成降级/部分答案/拒答（安全失败），
不是自信的错误答案——与「refusal over fabrication」宪法一致。

**四个杠杆**（前两个 v0.6 已在做，v0.7 系统化）：

| 杠杆 | 做法 | 现成范例 |
|---|---|---|
| 缩短乘法链（n↓） | 能确定化的环节不给模型 | trend_research 确定性期间遍历（模型自遍历会漏期/循环，实测） |
| 切断传播边（g↓） | verify-as-you-go：错误在第 k 步被拦、在第 k 步降级 | verify_citations + 口径闸；Phase 2 子目标检查点把它推进到步级 |
| 结构化传递 | 字段复制而非文本重释——值在传递中不变 | GraphState=TypedDict、subgoals=JSON、memory=结构化台账（不是工程洁癖，是传播率设计） |
| 并行分支不乘法 | 子目标图做 DAG 不做链，分支各自过闸、错误不跨分支复合 | compare 的按公司分解 |

**相关性警告**：闸门与模型犯同一类系统错误时，Σeₖ·gₖ 的界失效
（错误相关，不再独立）。双脑回归（heuristic 四集）+ 双档验收的
深层理由就是**相关性探测**，不是冗余——两套异质实现同时错的概率
才是真逃生率。

**度量先行（Phase 1 的真正使命）**：trace 记每步 (动作类型, 出错?,
闸门触发?) → eval 产出 **eₖ/gₖ 实测表**。无法管理不能度量的东西
——先装仪表，再拉长链。

> 每期共同纪律：TDD 红线先行；heuristic 四集不回归；llm 双档

### Phase 0：契约与叙事落文档（零代码风险，随首批实施）

- 本文档定稿；README 首节定位句升级（「Agentic RAG 问答引擎」→

- 验收：新读者从 README→DESIGN-v0.7 能在 10 分钟内讲清这个

### Phase 1：ReAct 显式化 + 步级观测

**做什么**：agent 循环的步级四元组进观测——
`agent[3] thought="扣非口径可能单列，换词再查" action=search{公司:茅台,期间:H1} obs=6块 gate=pass`
（thought=`resp["content"]` 截断；action=工具参数摘要；obs=块数+首块
doc；gate=该步证据的闸门结果）。`-v` 逐行、`--json` 结构化、步级耗时。

**为什么先做**：零行为变更（纯观测），且是后续 Planner/Memory 的
验收基础设施——没有步级观测，Phase 2/3 的回归只能看端到端指标。
更深一层是 §3 的**度量先行**：`eval --json` 增加 steps 出口，跑完
产出 **eₖ/gₖ 实测表**（按动作类型聚合的步错率与闸门逃生率）——
v0.7 要把链拉长，仪表必须先于扩程就位。

**验收红线**：现有 agent 题的 trace 可完整重放每步 Thought/Action/
Observation/闸门状态；eval 四集不变；eₖ/gₖ 表在真机产出一份。

### Phase 2：Planner-Executor（多跳规划，子目标显式化）

**做什么**：新增 `plan` 节点（仅 llm 模式）——LLM 输出结构化计划
JSON：`{subgoals: [{action: search, company, period, metric}...]}`
（≤5 个子目标）。**确定性校验器**：动作 ∈ 白名单、公司/期间与
理解先验一致（不一致以先验覆盖）、子目标数上限。校验失败 → 回退
现路径（understand→route 直进）。执行器复用 `run_search`；state
新增 `subgoals` 账本，三态 `pending/done/failed` 进 trace
（`plan:3子目标/完成2/弃1(检索不足)`）。

**检查点验证**（§3「切传播边」的步级落地）：每个子目标完成后，
其证据**先过闸**（数字在场+口径匹配）再进入下一子目标的上下文——
下游永不消费未验证的上游输出。failed → 有界重试 ≤1 → 仍败则跳过
并在答案里**声明缺口**（「已覆盖 A/B，未覆盖 C：检索不足」）——
带声明的部分答案 > 自信的错答案。

**覆盖面**：跨期对比（「2025 vs 2026 毛利率变化」——现 roadmap 项，
需按期间分解，decompose 只会按公司拆）；多指标对比（「营收和扣非
谁涨得快」）；compare 多于两家。trend/metric 单跳仍走原路（规划
成本不划算）。

**为什么不做成通用 planner**：白名单动作+先验校验把 planner 的
输出空间压到可判定——这是封闭世界契约的第 2/4 条在规划层的落地。
LLM 规划自由度=选择检索什么，不是选择做什么。

**验收红线**：新 eval 集「多跳规划 8 题」（跨期×多指标×三家对比）；
规划失败回退不劣于现状；heuristic 不进此节点；failed 子目标产出
**带声明的部分答案**（红线：不允许静默吞掉缺口）。

### Phase 3：Memory 三层（详细设计见 §7）

**L0 会话记忆（in-context）**：`chat` 子命令（REPL 多轮）——state 增加
`history`：近 3 轮全量，更早压缩为**结构化轮摘要**（understanding+verdict+
facts 字段，丢散文）；`understand` 先验扩为「上文继承」——只继承结构化
字段（公司/指标），永不继承自由文本；显式新实体覆盖继承。双脑同支持。

**L1 事实台账（verified_facts 表）**：键寻址
`(company, period, metric, caliber) → 值+同比+引用+覆盖+语料指纹`。
**写闸**：仅 `verdict=pass` 且口径闸未触发的事实可写（契约第 3 条）。
**读不豁免**：命中只省检索+生成（贵的那段），答案仍带原引用过
`verify_citations`（确定性、ms 级）——缓存的是已核实证据，不是结论。
**失效**：源 doc 指纹变 → 行作废；**追溯调整**：同键新行引用更新的
文档 → 旧行 superseded 保留审计（轻量双时间语义）。

**L2 固定语义资产（CLAUDE.md 的类比）**：仓库内 JSON（git 可 diff），
常载、体量 ≤2KB——alias 表（茅台→贵州茅台）、口径词典（营业收入↔
营业总收入）、锚点提示、版式 quirks（一行一块 vs 多行一块）。是**检索
导航知识而非答案事实**（不产事实，不违封闭世界）。晋升闸=eval 全绿+
人工审（系统可提议，不可自升）。

**为什么结构化台账而非向量库自由文本**：回写内容可验证（数值+引用），
命中即可对账；自由文本记忆的「记忆污染」无法闸。

**验收红线**：多轮题集（指代/省略/追问 10 题）；命中 vs 全流程答案
一致性 100%（值+引用）+ 加速比记录；重摄失效单测；**投毒探针红线**
（手插错值行必须被 verify 拦住或被指纹失效清掉，绝不允许直接出门）；
L0 压缩有界（10 轮会话不超预算且第 1 轮事实仍可答）；eval 四集不回归
（eval 默认隔离台账，防把检索测成记忆）。

### Phase 4：工具面扩展（白名单内）

**工具注册表**（首个真扩面，取代 v0.6 的「单一工具」决策——当时
防的是无边界扩面，白名单扩面不违背该决策的本意）：

1. `search`（现有，不动）
2. `metrics_table`：按 公司+期间 拉结构化指标行（复用 trend_skeleton
   的行解析），返回带口径标签的行——模型看得懂表格了，口径错配
   在证据侧就减少
3. `derive`：差分算子（Q2=H1−Q1、Q4=FY−Q3，同公司同指标同口径，
   前置校验 basis 对齐）——即原 Phase 3「单季差分层」的 Agent 化
   形态：派生行带「派生值：a−b=c（原文未直接披露）」标注+双操作
   数引用，**verify 时重算 ±0.01**。DESIGN-v0.6 §9 的 P2 算术恒等探针
   （归母−扣非=非经常合计等）并入 derive 的验收。

**明确不做**：浏览器、外部 API、模型写码执行（契约第 2 条）；
理由不是能力而是**可判定性**——这三个方向都会把「对账」变成
「无法对账」。

**验收红线**：「近 2 年每季度营收」8 单季全对（差分解锁 6→8）；
派生数字闸单测（出口重算不一致=编造降级）；工具误用回退单测。

## 5. 刻意不做清单（同样写进文档，防后人 re-litigate）

| 不做 | 理由 |
|---|---|
| ToT 全树搜索 | 预算爆炸×小模型；单线规划+先验覆盖已覆盖真实需求；树的价值在可回溯探索，我们的可回溯性由 trace+eval 承担 |
| 浏览器/外部 API 工具 | 封闭世界契约第 2 条 |
| 模型生成代码执行 | 幻觉面；算术走确定性 derive 算子 |
| 自由文本长期记忆（向量记忆库） | 回写不可闸→记忆污染不可判定；结构化台账可验证可失效 |
| 无界反思/多轮自我辩论 | 小模型死循环入口（实测）；有界 ×1 是纪律 |
| 通用 planner（动作空间开放） | 规划输出必须可判定（白名单+先验校验） |

## 6. 实施顺序与里程碑

```
Phase 0  文档契约批        ── 0.5 天（随首批代码同 PR）
Phase 1  ReAct 步级观测    ── 0.5 天（纯观测零行为变更 + eₖ/gₖ 度量出口）
```

### 7.0 调研快照（2026-10 核实，各取一件我们用的）

| 系统 | 机制 | 我们取什么 | 封闭世界裁决 |
|---|---|---|---|
| **Claude Code 记忆** | 三层：CLAUDE.md（常载精选）/ auto-memory 目录（一事实一文件 + MEMORY.md 索引按需加载）/ 对话压缩（过阈值摘要转存再清）；写入纪律「可推导的不存、先查重再更新、错的删除」 | 索引+按需加载（**上下文有界、存储无界**）；一事实一行原子性；更新不重复 | ✅ 全采纳（存储换 SQLite 行） |
| **Claude API memory tool + context editing** | 文件式六命令（view/create/str_replace/insert/delete/rename）客户端自编辑记忆 + 服务端清旧上下文（官方报告 ~29% 提升）；过阈值自动触发「先转存再清」 | 「记忆=可审计文件操作」与「压缩转存」的**配对**思想 | ✅ 采纳配对（L0 压缩 ↔ L1 落盘） |
| **MemGPT / Letta** | core（常驻自编辑）/ recall（对话库）/ archival（向量库）三层 + **sleep-time compute**（闲时离线整理记忆） | 分层思想；sleep-time → ingest 后离线预填台账（§7.6，可选默认关） | archival 向量层 ❌（自由文本回写不可闸） |
| **Mem0** | 事实抽取入库，经典 ADD/UPDATE/DELETE/NOOP 四算子（2026-04 起简化为 ADD-only 抽取+二次比对） | 写路径的**合并算子**语义 | ✅ 采纳为确定性 SQL 合并（§7.5） |
| **Zep / Graphiti** | 时间知识图谱：事实带**有效区间**、双时间轴（发生时间 vs 知道时间）、只失效不物理删除 | **追溯调整（restatement）版本语义**——财报同期间会被后续文件重述，这是金融域真实场景 | ✅ 采纳轻量双时间（§7.5 RESTATE） |
| **Letta 文件系统基准** | 「文件系统就够了吗」：纯文件记忆 LoCoMo 74% 反超知识图谱方案（后有方法学争议） | 简单可审计的存储 > 花哨结构——与「SQLite 行+键寻址」同路 | ✅ 佐证 |

### 7.1 设计公理（从约束倒推，六条）

1. **事实不可压缩，叙述才可压缩**——有损压缩一个数字=捏造一个数字。
   L0 压缩对话（语言，可摘要）；L1 永不压缩事实（证据，只能整体失效）。
2. **缓存证据，不缓存结论**——命中只省检索+生成（贵），答案仍带
   原引用过 `verify_citations`（便宜、确定性、ms 级）。
3. **写闸严于读闸**——与 `_self_check` 非对称信任同构：只有
   `verdict=pass` 且口径闸未触发的事实可写；读永远免费且可疑。
4. **爆的是上下文，不是存储**——SQLite 百万行无所谓，prompt token
   才贵。Claude 的解法是「索引+按需」；我们更强：**键寻址**
   （company+period+metric+caliber 精确匹配），连索引排序都不需要。
5. **记忆是错误放大器**——写错一条，后续每轮都在读它（0.95²⁰ 的账
   在记忆上更狠：单次幻觉变系统性污染）。对策：append-only+溯源+
   投毒探针红线测试。
6. **失效=语料指纹**——语义 TTL：manifest 指纹一变，相关记忆行立即
   作废。语料变了，记忆必须跟着变。

### 7.2 三层总图

```
┌─ L2 固定语义资产 ── CLAUDE.md 的类比 ──────────────────────┐
│   仓库 JSON 常载 ≤2KB · 晋升闸 = eval 全绿 + 人工审          │
│   alias 表 / 口径词典 / 锚点提示 / 版式 quirks               │
│   （检索导航知识，不产事实 → 不违封闭世界）                   │
├─ L1 事实台账 ── verified_facts 表 ─────────────────────────┤
│   键寻址 (company, period, metric, caliber) · 写闸=verify pass │
│   值+同比+引用+覆盖率+源指纹 · append-only+supersede         │
│   （已核实证据的缓存——「每条记忆都能对账」）                  │
├─ L0 会话记忆 ── history in-context ────────────────────────┤
│   近 3 轮全量，更早转结构化轮摘要 · 只继承结构化字段          │
│   （多轮指代/省略/追问；压缩只发生在这一层）                  │
└──────────────────────────────────────────────────────────┘
```

### 7.3 L0：会话记忆（压缩只在这里）

- 载体：`cli chat` REPL 子命令（多轮共享进程内 state；exit 即清）。
- 轮摘要格式（**结构化字段，非文本摘要**——压缩掉的只是散文）：
  `{q, understanding{intent,company,period,metric}, verdict, facts[(metric,value,yoy,cite)], coverage}`
- 窗口：近 3 轮全量 Q/A，第 4 轮起摘要化（预算见 §7.7）。
- 继承=传播边（长程可靠性视角）：只继承 understanding 字段、永不
  继承自由文本；显式新实体覆盖继承（新句出现「中际旭创」→ 覆盖继承的
  公司）；trace `memory:inherit(company)`；每轮照常过闸——继承不豁免。
- 双脑同构：heuristic 的规则回填与 llm 的上文继承共用同一 `history`。

### 7.4 L1：事实台账（核心层）

**表结构**（SQLite，Store 仍是唯一写入口——不变量 1 延伸）：

```sql
CREATE TABLE verified_facts (
  id INTEGER PRIMARY KEY,
  company TEXT NOT NULL, period TEXT NOT NULL,
  metric TEXT NOT NULL, caliber TEXT NOT NULL,
  value_raw TEXT, value_std REAL, unit TEXT, yoy TEXT,
  citations TEXT NOT NULL,   -- JSON [{doc_id, page, quote}]
  coverage REAL, verdict TEXT NOT NULL, run_id TEXT, created_at TEXT,
  source_doc_ids TEXT, doc_fps TEXT,   -- JSON 数组（溯源）
  superseded_by INTEGER REFERENCES verified_facts(id),
  supersede_reason TEXT       -- reingest / restated / conflict
);
CREATE INDEX vf_live ON verified_facts(company, period, metric, caliber)
  WHERE superseded_by IS NULL;   -- 部分索引：只索引活行
```

**写路径**（graph 出口处，verify 之后）：
`verdict=pass` ∧ 口径闸未触发 ∧ 源指纹全部当前 → 走 §7.5 合并算子。
双脑都写（heuristic 的答案同样可对账；run_id 记录来源脑）。

**读路径**（understand 之后、route 之前）：

```
probe = 台账[(company_norm, period, metric, caliber)]   # alias 归一后查
if probe 存在 ∧ probe.doc_fps 全部当前 ∧ 无更新文档覆盖同(公司,期间):
    answer = assemble(probe)                # 复用骨架行格式重组
    verdict2 = verify_citations(answer, probe.citations)   # 读不豁免
    verdict2=pass → trace memory:hit(...)，出口（省 agent/检索/生成）
    否则 → trace memory:stale(verify)，落回全流程
else → trace memory:miss，全流程（成功则回写）
```

**同问直取的效果**：llm 模式省 understand 之后的全部重活（agent 循环
~10s 级 → 组装+verify ~0.1s 级），且答案**可复现**（同值同引用）——
命中即确定性，这是比省时间更重要的性质。

### 7.5 合并算子（写路径的确定性 SQL，Mem0/Zep 语义的封闭世界版）

| 情形 | 算子 | 动作 | 理由 |
|---|---|---|---|
| 同键+同指纹+同值 | **NOOP** | 跳过 | 幂等；Claude「先查重、更新不重复」 |
| 同键+同指纹+异值 | **CONFLICT** | 追加新行，旧行 superseded(reason=conflict) + 告警 | 两次都 pass 却不同值=必有一错，进观测绝不静默 |
| 同键+源 doc 指纹已变 | **INVALIDATE** | 旧行 superseded(reason=reingest)，再正常写 | 语料变了记忆跟着变（公理 6） |
| 同键+新行引用**更新的**文档（同期间） | **RESTATE** | 旧行 superseded(reason=restated) 保留审计 | 财报追溯调整；Zep 双时间轴的轻量版 |

永不物理删除（append-only）——审计=对账的泛化：「这条记忆哪来的」
永远可答。**纠错即删除**是唯一例外：确认错误的行可删（Claude 记忆
纪律同款），删除必须留 run 记录。

### 7.6 L2：固定语义资产 + 可选的离线预填

**L2 内容**（`duizhang/assets/semantic_assets.json`，git 版本化）：

- `alias`：公司简称↔全称（把 D20 的硬编码归一表外置为数据）
- `caliber_lexicon`：口径变体词典（营业收入↔营业总收入、扣非全名…，
  D23 的边界知识沉淀）
- `anchor_hints`：各公司「主要会计数据」锚点提示（茅台 summary 锚
  泛化问题的数据面出口）
- `layout_quirks`：版式 quirks（一行一块需 stitch / 多行一块需行级切分）

**晋升闸**：系统可从重复纠错模式中**提议**增补（如 understand 连续
fallback 检测到新 alias），但晋升必须 eval 全绿+人工审——L2 不是答案
事实，verify_citations 管不到它，**闸换成 eval 套件**。

**可选扩展（默认关）——sleep-time 预填**：ingest 完成后离线对每个新
doc 跑一遍过闸抽取预填 L1（Letta sleep-time compute 的语料版）。台账
从「交互缓存」升格为「语料的物化视图」，冷启动即命中。代价=ingest
变慢+稀释「每条记忆来自一次真实过闸问答」的简单叙事。列为 Phase 3
完成后的独立开关实验，不进默认路径。

### 7.7 预算表（防爆炸的量化形态）

| 层 | 上下文预算 | 存储预算 |
|---|---|---|
| L2 | 常载 ≤2KB | 仓库 JSON，git 版本化 |
| L1 | 命中返回 ≤1 行/键（数百 token） | 无界：1,104 docs×指标×期数≈万级行，SQLite 无压力；真成本=陈旧面，指纹管 |
| L0 | ≤3 全轮 + ≤10 摘要行（约 1-2K token） | 进程内，不落盘（v0.7 不做跨会话对话持久化） |

### 7.8 隔离与开关

- `DZ_MEMORY`（默认 on；off=完全旁路，行为=v0.6.5）。
- **eval 默认隔离台账**（evalx 每轮清空或绕过读路径）：否则第 N 题
  命中第 1 题的缓存，把「检索能力」测成「记忆能力」。memory 专项
  评测显式开：指标=命中率、一致性、**加速比**。

### 7.9 验收红线（Phase 3）

1. 多轮题集 10 题（指代/省略/追问）双脑过；
2. 命中 vs 全流程：值+引用 100% 一致，加速比记录在案；
3. 失效单测：改 doc 重摄 → 活行清空，答案回到全流程；
4. **投毒探针（红线）**：手插错值行 → 读路径 verify 拦住或指纹失效
   清掉，绝不允许直接出门；
5. CONFLICT 单测：同键异值 → 旧行 superseded+告警，不静默覆盖；
6. L0 压缩有界：10 轮会话不超预算，且第 1 轮事实仍可答；
7. eval 四集不回归（隔离模式）。

### 7.10 反模式（不存清单——与刻意不做表同权重）

| 不存 | 理由 |
|---|---|
| 叙述/分析文本 | 每次重生成；缓存叙述=风格固化+陈旧风险，收益近零 |
| 未过闸的中间抽取 | verify 前的一切都是待验品，不是记忆 |
| 对话的向量嵌入检索 | 自由文本回写不可闸（§5 已列） |
| 用户偏好/画像 | 非事实域，v0.7 不需要——列为「允许但不做」，防 scope 蔓延 |
