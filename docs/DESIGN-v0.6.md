| | |

## 1. 定位修正

v0.5 是「LLM 填决策点的固定图」（agentic RAG 模式），拓扑编译期写死——
按 Anthropic 定义不是自主 agent。v0.6 把检索阶段交给模型：单一 search
工具 + 循环，模型自己决定查什么、查几次、何时收手。**出口闸门不动**：
agent 收集的证据照样过 generate→verify，自主检索不豁免对账。

```
llm 模式：  understand → route ─metric/compare→ agent_research（工具循环）→ generate → verify
heuristic： understand → route ─metric→ retrieve / compare→ decompose → grade⇄rewrite → generate → verify
```

## 2. 决策记录（每条都是真机踩出来的）

### D9 单一工具 + 原生 tools 协议（防过度设计）
qwen3.5:0.8b 经 Ollama 原生 tools 实测可靠（正确选工具、结构化参数）。
刻意不建工具注册表：一个 `search(query, company, period)` 已覆盖
metric/compare 真实需要；read_doc/list_docs 是 YAGNI。步数硬上限 6
（业界惯例：agent 循环必须有预算）。

### D10 幂等缓存 + 重复收手
0.8b 实测死循环：同一调用原样重复 6 步烧满预算。修复：调用签名去重
缓存，重复调用回缓存结果并提示换角度；**整批全重复 = 模型没有新问题
要问 → 提前收手**（6步12次 → 2步2次）。

### D11 理解先验优先于工具参数
小模型三次实测事故定义了工具默认值语义：
- 不传 company（单跳题）→ 全库检索被千家同类内容淹没 → **从
  understanding 继承**；多公司 understanding → 工具内逐家检索交错合并
- 幻觉 period（「半年度」传成 FY）→ 年报块洪水 → **期间以理解为准、
  参数只补空白**——理解是模型对原问题的结构化决定（含规则回填），
  工具参数是检索战术，冲突时先验赢
- 抽 period 时灵时不灵 → 空值从规则确定性匹配回填（与公司名纠偏对称）

原则：廉价结构化理解做先验，模型自主性用在「迭代检索策略」上——
这正是 0.8b 级小模型能可靠承担的那部分自主性。

### D12 证据按文档轮转 + Agent 检索词写进 effective_query
pool 插入序会让先查的一方包揽前排（单边答案，decompose 同款教训）；
原始口语 query 与证据零重叠会误拒（「哪家赚得多」没有指标词）——
Agent 实际用的检索词必须写进 effective_query 供下游打分。

## 5. v0.6.1 追加：切分审计与页级证据组装（2026-10-17）

> 触发：用户质询「PDF 切分怎么做的？overlap 怎么设置的」。答案是
> **overlap=0 且从未作为决策记录**——本节把欠账补上，并用实测数据
> 完成选型。全部数字来自中际旭创语料（10 docs / 8,768 chunks）。

### 5.1 切分现状审计（实测）

| 指标 | 数值 | 说明 |
|---|---|---|
| overlap | **0**（从未实现也从未记录） | 本节正式记录决策 |
| 表格块占比 | 4,287/8,768 = **49%** | 聚簇逻辑工作正常 |
| 块长分布 | P25=27 / P50=53 / P75=116 / P95=384 / max=680 字符 | 一半块很小（残行/表格碎片） |
| 真实 420 溢出切割 | 823/2,737 正文块 = **30%** | 算法造成的硬切 |
| 半句收尾表象 | 82% 正文块非句末符收尾 | **主因是 PDF 行拆句的源文本形态**，非算法切割 |
| 空表头块 | 718/4,287 = **17%** | 纯列名无数据行，检索噪声 |
| 母公司/合并口径 | 86 / 141 块混排 | 检索不分口径（挂起观察） |
| 数字注释覆盖 | 241/8,768 = 3% | 千分位+单位 400 处 vs 直书仅 66 处 |
| top-8 同页覆盖 | **5/5 查询每页最多 1 块** | 「相邻块共召回兜底」假设被证伪 |

**被自己的测量否决的提案**（记录完整过程，防止翻案）：
- **句边界切割**：模拟实测半句率 82%→81%（无改善）且块数 +60%——
  30% 溢出切割发生在无标点的数字密集文本（误分类为正文的表格），
  句号不存在，句边界无处可切。
- **文本 overlap**：与引用精确性冲突（块的证据归属产生歧义）；
  版式感知/语义/命题切分派业界也普遍 overlap=0，本决策与该派一致。
- **数字注释扩直书格式**：全库仅 66 处 vs 千分位 400 处，收益 3% 量级。
- **母公司/合并降权**：eval 全绿，问题被闸门兜住，等真实错答再修。

### 5.2 业界九方案对照与选型

| 方案 | 否决/入选理由 |
|---|---|
| 固定窗口+overlap / 递归边界切分 | overlap 与引用精确性冲突 |
| 版式感知切分 | **已是现状**（表格原子块） |
| 语义/命题切分、late-chunking | 需 embedding，违背全本地零依赖 |
| Contextual Retrieval | 摄取期每块一次 LLM 调用，0.8b 写定位摘要不可靠 |
| 页级大块切块 | 推翻已验证 1.0 的小块检索——为修问题砸正常部分 |
| 摄取端合并相邻块 | 不解决跨页断句，且需全库重灌 |
| **父子块 small-to-big（最小形态）** | ✅ **入选**：检索精度与生成上下文解耦，零新依赖 |

### 5.3 设计：页级证据组装（本次实施）

**问题定义**：检索准（小块 bm25 精确命中），但生成/校验只见孤立碎片——
半句的后续、表格的同行数据、数字与科目名都在兄弟块里，而 top-8
每页只出一个块（5.1 实测），上下文从不自动在场。

**改动边界（不过度设计的三条线）**：不改 ingest 切分逻辑、不动检索层、
不建层级索引。只改**生成证据组装**一个环节。

```
top hits ──取前 4 个命中──▶ 去重 (doc_id, page)
        ──每页一次 SQL（idx_chunks_doc 现成索引）──▶ 同页块按 seq 排序
        ──命中块为中心的 ±2 窗口（≤5 块/页）──▶ 页级证据单元
        ──总块数硬顶 20──▶ "[doc 第N页]\n块1\n块2…" 拼接进 generate 证据
verify：证据池同步用页级块集（citation 串匹配出的被引池=该页全部窗口块）
extractive：仍用原始命中块（引用归属与 verify 口径保持一致）
```

**配套：空表头过滤（先于补页，否则 17% 空壳块被一并补进上下文）**
`ingest_file` 落库前丢弃 `is_table 且 ≥3 位数字出现少于 2 次` 的块；
存量库 `ingest --rebuild` 重灌生效。

**验收门槛**：54 测试全绿；heuristic 双数据集与 llm agent 集 ≥ 现状
（1.0/1.0/1.0）；llm default 集 ≥ 0.875。
**风险与回退**：0.8b 面对页级长证据可能被稀释（上下文越长小模型越容易
失焦）——评估集是裁判，掉线即回退；改动集中在证据组装函数，回退干净。

**预期收益（对准 5.1 实测痛点）**：半句上下文补全（82% 非句末收尾）、
同页表格行聚齐（数字与科目分家）、verify 跨块误降级消除；检索噪声
-17%（空表头过滤后 LLM 证据窗口有效密度提升）。
