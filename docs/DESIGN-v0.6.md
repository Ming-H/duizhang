# 对账 v0.6 设计：真 Agent 环——模型自主检索

| | |
|---|---|
| 状态 | **已实施并真机验收**（2026-10-16，qwen3.5:0.8b 本地） |
| 范围 | llm 模式下 metric/compare 从固定管线改为工具循环（模型自主决定查什么、何时收手）；heuristic 固定管线原样保留 |
| 前置 | `DESIGN-v0.5.md`（Agentic RAG 图与 §5 v0.5.1 本地化） |

## 1. 定位修正

v0.5 是「LLM 填决策点的固定图」（agentic RAG 模式），拓扑编译期写死——
按 Anthropic 定义不是自主 agent。v0.6 把检索阶段交给模型：单一 search
工具 + 循环，模型自己决定查什么、查几次、何时收手。**出口闸门不动**：
agent 收集的证据照样过 generate→verify，自主检索不豁免对账。

```
llm 模式：  understand → route ─metric/compare→ agent_research（工具循环）→ generate → verify
heuristic： understand → route ─metric→ retrieve / compare→ decompose → grade⇄rewrite → generate → verify
```

## 2. 决策记录（每条都是真机踩出来的）

### D9 单一工具 + 原生 tools 协议（防过度设计）
qwen3.5:0.8b 经 Ollama 原生 tools 实测可靠（正确选工具、结构化参数）。
刻意不建工具注册表：一个 `search(query, company, period)` 已覆盖
metric/compare 真实需要；read_doc/list_docs 是 YAGNI。步数硬上限 6
（业界惯例：agent 循环必须有预算）。

### D10 幂等缓存 + 重复收手
0.8b 实测死循环：同一调用原样重复 6 步烧满预算。修复：调用签名去重
缓存，重复调用回缓存结果并提示换角度；**整批全重复 = 模型没有新问题
要问 → 提前收手**（6步12次 → 2步2次）。

### D11 理解先验优先于工具参数
小模型三次实测事故定义了工具默认值语义：
- 不传 company（单跳题）→ 全库检索被千家同类内容淹没 → **从
  understanding 继承**；多公司 understanding → 工具内逐家检索交错合并
- 幻觉 period（「半年度」传成 FY）→ 年报块洪水 → **期间以理解为准、
  参数只补空白**——理解是模型对原问题的结构化决定（含规则回填），
  工具参数是检索战术，冲突时先验赢
- 抽 period 时灵时不灵 → 空值从规则确定性匹配回填（与公司名纠偏对称）

原则：廉价结构化理解做先验，模型自主性用在「迭代检索策略」上——
这正是 0.8b 级小模型能可靠承担的那部分自主性。

### D12 证据按文档轮转 + Agent 检索词写进 effective_query
pool 插入序会让先查的一方包揽前排（单边答案，decompose 同款教训）；
原始口语 query 与证据零重叠会误拒（「哪家赚得多」没有指标词）——
Agent 实际用的检索词必须写进 effective_query 供下游打分。

## 5. v0.6.1 追加：切分审计与页级证据组装（2026-10-17）

> 触发：用户质询「PDF 切分怎么做的？overlap 怎么设置的」。答案是
> **overlap=0 且从未作为决策记录**——本节把欠账补上，并用实测数据
> 完成选型。全部数字来自中际旭创语料（10 docs / 8,768 chunks）。

### 5.1 切分现状审计（实测）

| 指标 | 数值 | 说明 |
|---|---|---|
| overlap | **0**（从未实现也从未记录） | 本节正式记录决策 |
| 表格块占比 | 4,287/8,768 = **49%** | 聚簇逻辑工作正常 |
| 块长分布 | P25=27 / P50=53 / P75=116 / P95=384 / max=680 字符 | 一半块很小（残行/表格碎片） |
| 真实 420 溢出切割 | 823/2,737 正文块 = **30%** | 算法造成的硬切 |
| 半句收尾表象 | 82% 正文块非句末符收尾 | **主因是 PDF 行拆句的源文本形态**，非算法切割 |
| 空表头块 | 718/4,287 = **17%** | 纯列名无数据行，检索噪声 |
| 母公司/合并口径 | 86 / 141 块混排 | 检索不分口径（挂起观察） |
| 数字注释覆盖 | 241/8,768 = 3% | 千分位+单位 400 处 vs 直书仅 66 处 |
| top-8 同页覆盖 | **5/5 查询每页最多 1 块** | 「相邻块共召回兜底」假设被证伪 |

**被自己的测量否决的提案**（记录完整过程，防止翻案）：
- **句边界切割**：模拟实测半句率 82%→81%（无改善）且块数 +60%——
  30% 溢出切割发生在无标点的数字密集文本（误分类为正文的表格），
  句号不存在，句边界无处可切。
- **文本 overlap**：与引用精确性冲突（块的证据归属产生歧义）；
  版式感知/语义/命题切分派业界也普遍 overlap=0，本决策与该派一致。
- **数字注释扩直书格式**：全库仅 66 处 vs 千分位 400 处，收益 3% 量级。
- **母公司/合并降权**：eval 全绿，问题被闸门兜住，等真实错答再修。

### 5.2 业界九方案对照与选型

| 方案 | 否决/入选理由 |
|---|---|
| 固定窗口+overlap / 递归边界切分 | overlap 与引用精确性冲突 |
| 版式感知切分 | **已是现状**（表格原子块） |
| 语义/命题切分、late-chunking | 需 embedding，违背全本地零依赖 |
| Contextual Retrieval | 摄取期每块一次 LLM 调用，0.8b 写定位摘要不可靠 |
| 页级大块切块 | 推翻已验证 1.0 的小块检索——为修问题砸正常部分 |
| 摄取端合并相邻块 | 不解决跨页断句，且需全库重灌 |
| **父子块 small-to-big（最小形态）** | ✅ **入选**：检索精度与生成上下文解耦，零新依赖 |

### 5.3 设计：页级证据组装（本次实施）

**问题定义**：检索准（小块 bm25 精确命中），但生成/校验只见孤立碎片——
半句的后续、表格的同行数据、数字与科目名都在兄弟块里，而 top-8
每页只出一个块（5.1 实测），上下文从不自动在场。

**改动边界（不过度设计的三条线）**：不改 ingest 切分逻辑、不动检索层、
不建层级索引。只改**生成证据组装**一个环节。

```
top hits ──取前 4 个命中──▶ 去重 (doc_id, page)
        ──每页一次 SQL（idx_chunks_doc 现成索引）──▶ 同页块按 seq 排序
        ──命中块为中心的 ±2 窗口（≤5 块/页）──▶ 页级证据单元
        ──总块数硬顶 20──▶ "[doc 第N页]\n块1\n块2…" 拼接进 generate 证据
verify：证据池同步用页级块集（citation 串匹配出的被引池=该页全部窗口块）
extractive：仍用原始命中块（引用归属与 verify 口径保持一致）
```

**配套：空表头过滤（先于补页，否则空壳块被一并补进上下文）**
`ingest_file` 落库前丢弃 `is_table 且「≥3 位且非 20xx 年份」的数字少于
2 个`的块。实施修正：测试抓出纯年份列头（「项目 2026年半年度
2025年半年度」——两个年份即凑满 2 个数字）逃过初版判据，年份是列
标签不是数据，已排除。重灌实测：8,768 → 7,873 块（**-895，-10.2%**）。

**验收结果（2026-10-17，57 测试全绿含 3 组新增）**：
| 组 | 结果 | 门槛 |
|---|---|---|
| heuristic · default | 1.00/1.00/1.00 | ≥1.0 ✓（pytest 阈值测试背书） |
| heuristic · agent | 1.00/1.00/1.00 | ≥1.0 ✓ |
| llm · agent | 1.00/1.00/1.00 | ≥1.0 ✓ |
| llm · default | 0.875/0.875/1.00 | ≥0.875 ✓ 持平 |

定性（innolight 2026H1 营收题）：0.8b 此前直接判 no-evidence，页级
证据后能生成答案（trace: generate:llm），兄弟块（同页股本句）进入
证据视野；verify 照常兜底。母公司 0.00 表仍排第 1——口径降权按
5.1 挂起观察，未动。

**风险与回退**：0.8b 面对页级长证据可能被稀释——评估集是裁判，
掉线即回退；改动集中在证据组装函数，回退干净。

**预期收益（对准 5.1 实测痛点）**：半句上下文补全（82% 非句末收尾）、
同页表格行聚齐（数字与科目分家）、verify 跨块误降级消除；检索噪声
-17%（空表头过滤后 LLM 证据窗口有效密度提升）。

## 6. v0.6.2 追加：trend 意图与跨期研究（2026-10-17）

> 触发：用户实测「最近几个季度营收/利润的趋势，值得投资吗」得到
> 表格残渣——被误路由 summary（单文档假设），且系统对跨期聚合
> 完全没有支持（Roadmap 欠账）。跨期趋势是财报分析最高频的真实
> 问法，本节补上。

### 6.1 根因

| 层 | 缺陷 |
|---|---|
| understand | 无 trend 意图；「趋势/最近几个季度」被 0.8b 判 summary |
| summarize | 单文档假设（选最近一份），关键词行抓取产出表格残渣 |
| 检索 | period 单值——跨期问题需要遍历该公司全部报告期 |

### 6.2 设计

**意图**：新增 `trend`（跨期趋势/多期对比；投资建议类问题也归 trend
——用数据回答，不拒答不瞎答）。判定优先级 compare > trend > summary
> metric（对比更具体；LLM 判 summary 但 query 含趋势词时守卫纠正，
与 compare 守卫同款）。

**trend_research 节点（确定性，双模式共用）**：
```
该公司全部报告期 → 时间序（period 后缀映射月份：Q1→3/H1→6/Q3→9/FY→12）
→ 「季度」类问法取季度粒度报告期，否则全部粒度，最近 6 期
→ 每期一次 doc_scope 检索（营业收入 净利润 同比，k=3）
→ 按时间升序合并进 hits（页级证据自动跨期生效）
→ trace "trend:N期" → generate → verify（闸门照常，多期不豁免）
```
**生成纪律（实施修正）**：初版让 LLM 直生成多期长答案——0.8b 实测
自相矛盾（编造不存在的报告期、陷入「OCR 修正推断」螺旋），正是
§5.3 预警的长上下文稀释。改为**确定性骨架 + LLM 归纳段**：
- 骨架（确定性）：每期挑一句含数字的营收/净利润句 + 该期引用，
  按时间升序拼装——引用 100% 真实，闸门零风险
- 归纳段（可选 LLM）：只喂骨架本身，两三句趋势方向，禁止新数字；
  失败则只有骨架
- 投资建议免责声明由代码确定性追加，不靠模型自觉

**否决的备选**：让 Agent 环自己逐期调工具（0.8b 实测会在第 2 步
死循环/漏期，确定性遍历可靠且零 LLM 成本）；扩展 decompose（它是
按公司分解，语义不同）。

**验收（2026-10-17，60 测试全绿）**：用户原始问句（含投资建议）
得到六期营收/净利/同比逐期骨架（2024Q3→2026H1，417.8 亿
+182.49% 在场）+ 代码追加免责声明，verify:pass(0.882)。实施中
追加的三处修正：① 归纳段数字禁令由代码执行（0.8b 实测自己换算
量级且算错「7 万亿/断崖下跌」，宁缺毋滥直接丢弃）；② 骨架候选池
= 每期首命中页全页块（检索被节标题块占位，钱在同页兄弟块——
2026H1「主要会计数据」标题块挤掉营收行，实测）；③ verify 证据池
与骨架候选池同源（引用串同页但 hits 首块正文没数字，文本级重叠
实测崩到 0.119 误降级）。

## 7. v0.6.3 追加：innolight 真值驱动的四组修复（2026-10-19）

背景：中际旭创真值语料（10 docs / 7,873 chunks）上 6 处手跑失败，
真值全部人工核对。四组修复全部 TDD（RED→GREEN），innolight 评估集
从 14 题扩到 19 题（新增 5 道真值题，验收从手跑变一条命令）。

### D18 裸年份→FY（收益最大：当天 6 处失败的共同根因）

**根因（实测）**：query 只有年份没有期间词（「中际旭创 2025 年营业
收入多少」）时 `period_hints` 返回空 → 期间不限定 → Q1/H1/FY 文档
混排：营收题答成 Q1 的 66.7 亿（FY 真值 38,239,935,640.67），增长
率题答成 Q1 同比 37.82%（FY 同比 60.25%）。
**修法**：期间词全部落空后，`query_years(query)` 非空 → `["FY"]`
（默认年报口径，年份判定复用 query_years 含口语二位「25年」）；
understand prompt 同步加「仅提年份不提期间也算 FY」。消费端无需改：
retrieve/agent 的 allowed 为空本来就回退未过滤结果（该公司无 FY
文档时不误拒），route 期间守卫按年份全局判（2027/2023 照常拒）。
**验收**：裸年份题 heuristic/llm 双模式均答 38,239,935,640.67
（全部引用来自 2025FY），增长率题答 60.25%。

### D13 引用格式解耦（空白归一）

**根因（实测）**：0.8b 手写引用的空格会漂移（「第 8 页」/
「doc_id第8页」粘连），`chunk.citation` 精确子串匹配不认 →
`has_citation` 挂 → cov=0.8 的有据答案仍 degraded，compare 题结论句
被降级抽取式顶掉。低频漂移（当日采样 1/4），D18 修复前期间混排
放大了触发面。
**修法**：`answer._cite_norm` 剥尽空白后比较，三处接线同一口径——
`citation_coverage` 的被引池、`has_citation`（正则在归一化答案上跑）、
generate 的 cited 抽取。引用语义（doc+页）不变，只是格式解耦。

### D16+B2 口径行抽取（拼接 + 口径守卫，三层）

**根因（实测）**：2025Q1 主要会计数据表把扣非行切成相邻块——
seq4 纯标签（归属于上市公司股东的扣除非经常性损益的净利润（元））/
seq5 光数值（1,568,385,287.19）。光数值块零词面检索召不回，标签块
无数字被打分强降权 → 扣非题被页 10「标签+数字齐全」的归母行抢答
（1,582,876,128.67 顶掉 1,568,385,287.19）。
**修法（三层）**：
- **拼接**：`stitch_adjacent`（metric 意图、双模式）——命中块与
  同页相邻块互补（一侧纯标签 CJK≥6 无数字、一侧纯数值零汉字）时
  拼成整行合成块，标签在前、数值块的 num_notes 跟随；
- **trend 口径守卫**：`pick()` 跳过含「扣除/扣非」的行（默认口径
  =归母；require 含「扣非」时放行）——扣非行词面同样含「净利润」，
  先到先得实测 15.7 亿顶掉 15.8 亿；
- **extractive 口径守卫**：问句未提「扣」时扣非句不作候选——拼接后
  扣非行标签+数字齐全，rewrite 追加的通用词（净利润/扣非净利润）
  使其词面全中，实测顶掉营收行（25 年年报营收答成扣非
  10,710,053,246.51）。宁缺毋滥：口径不符不作候选而非降权。
**验收**：扣非题答 1,568,385,287.19（verify:pass 0.956）；归母题
1,582,876,128.67；营收题 38,239,935,640.67 领衔。

### D14 前置封顶 + 归因跳过

`front_key_table`（从 agent_research 内联块抽出便于单测）：主要会计
数据表页前置保留，两条收口——①前置块数 ≤8（整页前置长页 12+ 块会
淹没 Agent 自己收集的证据，真值行集中在页首前 8 块）；②归因题
（原因/为什么/为何/变动）跳过前置——要叙事证据句，表格行前置只会
挤掉归因句。

### 顺手修：verify 证据池 = 页级集合 ∪ hits

`page_evidence` 只装 hits[:4] 的页窗口而 extractive 从 hits[:8]
抽句——rank 5–8 的被引块（拼接行常排中段）缺席使正确答案被误标
degraded（扣非实测 0.395）。verify_citations 的池改为 evidence ∪
hits，与 coverage 层「cited beyond rank4 必须计数」同哲学。
