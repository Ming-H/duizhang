# 对账 duizhang：一个财报 RAG 的设计与踩坑实录

> 面向想理解「为什么这样设计」的读者。结构借鉴 Google design doc 的
> 决策记录（每条含备选与否决理由）、Meta 工程博客的事故复盘叙事、
> OpenAI cookbook 的「可复现命令 + 实测数字」。所有数字来自本仓库
> 在真实语料上的运行，复现命令附在每节末尾。

## TL;DR

带证据链纠错环的财报 RAG：LangGraph 编排 Corrective-RAG，SQLite FTS5
磁盘倒排做检索，每个答案逐句挂 `[公司_报告期 第N页]` 引用，对不上账
自动降级或拒答。当前语料 1,104 份 A 股财报/研报、60.7 万 chunk，
单机（M1/8GB）稳态检索 39ms、内存 0.03GB、增量摄取秒级。

```
# 30 秒复现（零 API key）
pip install -r requirements.txt
python -m duizhang.cli ingest samples/
python -m duizhang.cli ask "欧科亿 2026 年半年度预计净利润多少"
python -m duizhang.cli eval
```

## 一、系统鸟瞰

```
离线：PDF/MD ─→ 文件名元数据 ─→ 页眉剥离 ─→ 表格感知分块 ─→ 数字归一化
                （manifest 指纹增量：增/改/删自适应，幂等）
                     ↓
              sqlite（docs / chunks / fts_w / fts_c / manifest）

在线（LangGraph 状态机）：
  问题 → route（三分类 + 期间守卫）
        → retrieve（双轨 FTS5 RRF + 公司过滤 + 同义扩展 + 期间硬过滤）
        → grade_docs ─不足→ rewrite_query ─≤1次→ retrieve   # 有界纠错环
        → generate（heuristic 抽取式 / LLM grounded）
        → verify_citations（引用覆盖率 <0.45 → 降级；无据 → 拒答）
```

## 二、五个核心决策的推理链

### D1 表格原子分块 —— 财报的事实住在表格里

**问题**：财报 42% 的内容是表格；通用 RAG 的固定长度字符切分会把
`营业收入 520,053,589.94 345,593,109.95 50.48%` 这行拦腰斩断——
指标名与数值分家，等于销毁证据。

**备选**：① 固定 512 字符切分（通用方案）；② 语义模型切分（贵且不可控）；
③ 逐行分类聚簇（本文）。

**决策**：数字密集、无句号的短行判定为表格行，连续聚簇成原子块永不跨块；
正文按段落边界切 ~420 字；逐页处理让页边界天然保护跨页大表。
判定规则总共 6 行（`ingest._is_table_line`），零模型零成本。

**实测后果**：全库 42.1% 的块是完整表格块；「海伦哲第一季度营业收入」
直接命中含答案的表格行。

### D2 双轨检索与 RRF —— 词法两条腿互补

**问题**：中文词法检索有两条失败路径——分词错误（专业术语被切碎）和
词面鸿沟（问法与写法不同词）。

**决策**：jieba 词级 + 字级 trigram 两轨各取 top-k*3，RRF(k=60) 融合。
字轨对分词错误免疫（子串命中），词轨对语义密度敏感；融合不调权重，
排名互补是免费的鲁棒性。

**踩过的坑（值得抄走）**：v0.4 初版把字轨查询写成「空格整段短语」，
`"预计净利润多少"` 作为连续子串在原文中**永远不存在**（被年份隔开），
答案块在字轨零命中、排序崩塌。修复：字轨也按词 token 切短语。
教训：**换检索引擎时，查询语义的等价性要逐轨道验证，不能只看接口签名**。

### D3 Corrective-RAG 有界纠错环 —— 状态机的纪律

**问题**：检索不足时怎么办？无脑重试是状态机反模式（不可预测、可无限循环）。

**决策**：`grade_docs` 评分不足 → `rewrite_query`（补财报术语）→ 重检索，
**retries ≤ 1**，再不足则拒答。用 LangGraph 条件边实现，每次执行的
trace 里可见（`grade:1.0 insufficient → rewrite → grade:7.0 ok`）。

**配套守卫**（每个都是真实失败换来的）：
- 期间守卫：问 2030 年（库中无此报告期）直接拒——年份来自元数据，不靠模型
- 期间硬过滤：问「半年度」时年报/季报全是噪声，过滤比加权诚实
- 归因同义扩展：财报写因果用「主要系…影响」，与口语「原因」零词面重叠，
  不扩则归因块进不了召回

### D4 FTS5 磁盘倒排 —— 容量与内存解耦

**问题**：v0.3 自研内存倒排 60.7 万块要 1.8GB、每次增量后全量重建 117 秒；
线性外推全 A 股 5 年（3,000 万块）需 90GB 内存——本机差一个数量级。

**备选与否决**：ES（单机 JVM 是负资产）/ 向量库（增益未证明）/
自研磁盘倒排（重复造 FTS5）。

**决策**：SQLite FTS5 双虚拟表（unicode61 词轨 + trigram 字轨），
fts rowid 对齐 chunks.rowid，bm25() 打分，RRF 融合语义不变。

**实测后果**（同机同库对比，验收记录）：

| 指标 | v0.3 内存倒排 | v0.4 FTS5 |
|---|---|---|
| 启动时间 | 117s（重建）/ 5s（pickle 热启） | **0.05s** |
| 内存常驻 | 1.8 GB | **0.03 GB** |
| 检索延迟（稳态） | 9 ms | 39 ms |
| 增量摄取 | ~3 min（含重建） | **0.8 s** |
| 全库 retrieval@3 | 0.75 | **0.875** |
| 额外产物 | 485MB pickle 缓存 | 无（DB ~720MB 自含） |

延迟 9→39ms 是代价，换来容量与内存解耦 + 免重建增量。
PRAGMA（mmap + 200MB 页缓存）与「两轨轻列、正文延迟取」两个优化
把首轮 618ms 压到稳态 39ms。

### D5 对账校验 —— 宁可降级，不可编造

**问题**：LLM 生成的答案如何保证不编？

**决策**：三道闸——生成 prompt 强制页码引用、无据必答「原文中没有找到
依据」；`verify` 节点算**引用覆盖率**（答案句 token 与被引块的重叠率），
<0.45 自动降级为抽取式（从命中块抽证据句，永远有真凭实据）；期间守卫
与域词守卫管住入口。默认 heuristic 模式全程零 LLM。

## 三、事故复盘三则（postmortem 摘要）

### P1 幽灵旧块：更新路径的对称性缺失

**现象**：重摄取某文档后，检索仍命中旧页眉块，新块「不在」。
**根因**：更新时内存里换了新块，但 SQL 只 `INSERT OR REPLACE`——
块序号随重摄取变化，旧 id 的行不会被覆盖，新旧块在库里并存。
**修复**：更新路径先 `DELETE WHERE doc_id=?` 再插（`store.drop_doc`）。
**防线**：`test_readd_after_drop_no_ghost` 永久回归。
**通用教训**：**内存态与持久态的双写，删除语义必须对称**——
只想到「写」没想到「删」是这类 bug 的统一形状。

### P2 页眉逃逸：一行空格打败了逐字比对

**现象**：页眉剥离对部分页失效，答案被「公司名+报告标题」噪声块污染。
**根因**：PDF 文本抽取的空格位置逐页漂移（`2026年` vs `2026 年`），
逐字相同的判定失效——出现频率分散，过不了 30% 阈值。
**修复**：比对前归一化空白（`re.sub(r'\s+', '')`）。
**通用教训**：**文本相等性判定永远先定义归一化**，PDF 抽取的
「视觉相同」与「字节相同」是两回事。

### P3 测试清库：共享状态的代价

**现象**：跑了一次 pytest，60.7 万块的真实语料库被清空。
**根因**：CLI 测试用相对路径 `duizhang.db`，测试进程的孤儿清理逻辑
把真实库的全部文档判为「测试范围外的孤儿」删除。
**修复**：`DZ_DB` 环境变量隔离测试数据库；测试走 tmp_path。
**通用教训**：**任何会写持久状态的代码，测试必须显式隔离存储位置**；
「默认路径」在测试语境里就是共享全局变量。

## 四、版本实测总表

| 版本 | 检索 | 关键数字 |
|---|---|---|
| v0.1 | rank_bm25 纯 Python | 5 文档毫秒级；60 万块单查 **4.9s**（不可用） |
| v0.2 | 自研倒排 + numpy | 60 万块 9ms；1.8GB 内存；117s 重建 |
| v0.4 | SQLite FTS5 | 39ms 稳态；0.03GB；启动 0.05s；增量 0.8s |

## 五、扩展路径（按触发条件）

- **向量第三路**：bge-small-zh + 第三轨 RRF。触发条件：排行榜证明
  「词法+字轨」在口语化问题上的增益缺口 > 运维成本
- **rerank 层**：cross-encoder 精排 top-20。触发：retrieval@3 停滞
- **ES 平移**：多查询方 / 跨机部署时，`fts.search` 是唯一需要替换的函数
- **跨期对比**：结构化指标抽取 + 时序连接（「2025 vs 2026 毛利率变化」）
